Consumo de um Web Service

Informações do Projeto

Arquitetura e Lado do Servidor

O projeto consistiu no desenvolvimento, publicação e consumo de um Web Service distribuído fundamentado no padrão SOAP (Simple Object Access Protocol), abrangendo a arquitetura completa entre servidor (Server) e cliente (Client). O objetivo central foi consolidar os conceitos da Arquitetura Orientada a Serviços (SOA), permitindo a integração de sistemas heterogêneos por meio de serviços reutilizáveis e interoperáveis. Utilizando a linguagem Java na IDE Eclipse com o servidor Apache Tomcat, a lógica de negócio foi estruturada com anotações JWS para expor serviços funcionais — como automação de saudação baseada no horário e um gerador de senhas customizáveis —, garantindo a troca de mensagens padronizadas em formato XML através do contrato WSDL.

Execução e Consumo via Cliente

Para validar a comunicação distribuída, foi desenvolvido o módulo cliente responsável por consumir os serviços disponibilizados pelo servidor em tempo de execução. Através de requisições transacionais processadas via protocolo SOAP, a aplicação cliente interage diretamente com o ecossistema remoto, permitindo invocar operações e receber respostas estruturadas de forma síncrona. Os testes e a execução via console (Prompt de Comando) demonstram a eficiência na comunicação entre sistemas independentes, evidenciando o funcionamento fluido da arquitetura orientada a serviços na prática.

Implementação

A implementação técnica foi dividida em quatro etapas fundamentais, cobrindo todo o ciclo de vida de uma aplicação distribuída:

Desenvolvimento do Web Service (Servidor):

No projeto SoapHelloWS, dentro do pacote ws.hello, criou-se a classe SoapHelloWS.java. A classe foi decorada com a anotação @WebService e seus métodos com @WebMethod. Foram programadas duas regras de negócio: a emissão de uma saudação dinâmica com data e hora formatadas de acordo com o horário do servidor e um gerador de senhas seguras configurável por parâmetros de tamanho, inclusão de números e caracteres especiais.

Publicação do Serviço e Contrato WSDL:

A partir das anotações JWS, o serviço foi publicado e seu contrato estrutural WSDL foi disponibilizado pelo servidor Apache Tomcat na porta 8080, permitindo o mapeamento remoto dos métodos disponíveis.

Validação Transacional com SoapUI:

O contrato WSDL foi importado na ferramenta de testes SoapUI. Foram validadas as requisições SOAP para o método saudacao() e para o método gerarSenha(), inspecionando os envelopes XML de envio e resposta para garantir a integridade da comunicação.

Construção do Cliente Java e Portabilidade (JAR Executável):

No projeto SoapHelloClient, utilizaram-se assistentes da IDE para gerar os proxies de comunicação remota baseados no WSDL. Na classe SoapHelloClient.java, desenvolveu-se a interface de terminal que lê os parâmetros do usuário via teclado e dispara as chamadas remotas ao servidor tratando exceções RemoteException. Para assegurar a portabilidade total, o projeto cliente foi empacotado como um arquivo Runnable JAR contendo todas as dependências do Apache Axis embutidas, permitindo sua execução autônoma via Prompt de Comando (CMD) do Windows.
